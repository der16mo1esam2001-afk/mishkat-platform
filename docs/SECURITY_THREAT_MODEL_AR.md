# نموذج التهديدات والأمن — مِشكاة

## الأصول الحساسة
- سجلات صحية مستعارة وملاحظات سريرية وموافقات.
- مواقع شبكات المياه وقراءات الحساسات وعينات الجودة.
- مواقع المزارع وبيانات المحاصيل والتربة والإنتاج.
- بيانات العدادات والطاقة والمعدات.
- ملفات المتعلمين والتقييمات والتفضيلات وبيانات القاصرين المحتملة.
- رموز الهوية ومفاتيح API وسجلات التدقيق.

## حدود الثقة
1. المتصفح غير موثوق؛ لا يوضع فيه سر قاعدة بيانات أو مزود نموذج.
2. API هي نقطة الدخول الوحيدة إلى قواعد البيانات.
3. قواعد البيانات الخمس لا تستقبل اتصالات خارجية منشورة من Compose.
4. موصلات البيانات الخارجية تعامل استجابة الطرف الثالث كمدخل غير موثوق وتتحقق من مخططها وحدودها.
5. أي تكامل مع أنظمة تشغيل صناعية أو طبية يتطلب طبقة وسيطة ومراجعة قطاعية.

## التهديدات والضوابط

| التهديد | الضابط المطلوب |
|---|---|
| تسريب بيانات مستخدم إلى مستخدم آخر | JWT موثق + RLS + اختبار A/B لكل جدول |
| حقن SQL | استعلامات parameterized، ومنع أسماء جداول ديناميكية من مدخل المستخدم |
| كشف الأسرار في المتصفح | متغيرات خادم/مدير أسرار، ومسح Git والتاريخ |
| إدخال محتوى ضار من مصدر خارجي | تحقق مخطط وحدود الحجم، وتعقيم العرض، وعزل مهام الاستيراد |
| إساءة استخدام موصل API | تحقق هوية، وحدود طلبات، وفترات زمنية محدودة، وسجل تدقيق |
| تسريب بيانات صحية إلى مزود AI | لا يُرسل شيء في الإصدار الحالي؛ يتطلب لاحقاً موافقة صريحة وعقود معالجة وتقليل بيانات |
| الاستدلال الخاطئ من مؤشر إحصائي | وسم نوع البيانات ومقياسها وحدودها ومصدرها |
| تلاعب بقياسات حساسات | حفظ raw payload، ومعرف الجهاز، وجودة القياس، وسجل معايرة |
| التحكم غير الآمن في أصول حيوية | لا يوجد تحكم آلي في هذه النسخة؛ interlocks وموافقة مشغل عند إضافة هذه الوظيفة |
| الاعتماد على جلسة تطوير محلية | تعطيل `DEV_AUTH_ENABLED` قبل أي نشر، واستخدام مزود هوية حقيقي |

## إعداد التطوير المحلي ليس إنتاجاً

- رمز التطوير ثابت الهوية ومخصص للاختبار المحلي ومربوط بعنوان loopback في Compose.
- كلمة مرور قواعد البيانات تُحدد من `.env`، ولا تستخدم القيم الافتراضية خارج جهاز تجريبي.
- لا توجد مراجعة اختراق أو شهادة امتثال مرفقة.
- PostGIS وRLS في المخططات لا يغنيان عن اختبار الصلاحيات الفعلية.

## بوابات أمان قبل الإنتاج

1. اعتماد نموذج التهديد مع مالكي المنتجات والخبراء القطاعيين.
2. بناء تدفق هوية فعلي مع MFA عند الحاجة وPKCE/session cookies.
3. تنفيذ اختبارات عزل بين المستخدمين والمؤسسات في كل قاعدة.
4. فحص الثغرات والتبعيات وOWASP ASVS 5.0.0.
5. إعداد CSP وHSTS وTLS وإدارة أسرار وتدويرها.
6. تفعيل نسخ احتياطية واختبار استعادة موثق.
7. اختبار اختراق مستقل وخطة استجابة للحوادث.
8. تحديد الاحتفاظ والحذف والتصدير ومواقع المعالجة لكل فئة بيانات.
