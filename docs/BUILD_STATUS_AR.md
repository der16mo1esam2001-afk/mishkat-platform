# تقرير حالة بناء مِشكاة — النسخة 0.2.0

تاريخ التحديث: 14 نوفمبر 2026.

## ما أضيف في هذه النسخة

- حماية إعدادات الإنتاج: رفض وضع التطوير أو CORS العام أو إعدادات الهوية الناقصة أو القيم الافتراضية المعروفة عند `ENVIRONMENT=production`.
- Security Headers، ومعرف طلب `X-Request-ID`، ومنع التخزين المؤقت لاستجابات API.
- تهيئة مجمعات قواعد البيانات بشكل مستقل حتى لا يمنع تعطل قاعدة واحدة فحص القواعد الأربع الأخرى.
- API لسجل نشاط كل مجال: عمليات الاستيراد، النماذج المسجلة، وأحداث التدقيق المملوكة للمستخدم.
- مساحة NEXORA عملية أولية: ملف تعلم للبالغين فقط، موافقة مرتبطة بإصدار سياسة، سجل موافقات append-only، أهداف تعلم، ومسارات تعلم.
- سحب موافقة NEXORA يمنع إنشاء الأهداف والمسارات وتعديل أهداف التعلم. تظل السجلات السابقة محفوظة حتى تطبيق سياسة حذف/احتفاظ مكتملة.
- تصدير ملف NEXORA وأهدافه ومساراته وسجل موافقته بصيغة JSON للحساب المصادق عليه.
- Migration `database/nexora/03-learner-consents.sql` قابلة لإعادة التنفيذ، مع سكربت Windows لقواعد NEXORA الموجودة مسبقاً.
- Docker API image يعمل بمستخدم غير root، وfilesystem للقراءة فقط، و`no-new-privileges`، وحذف capabilities غير الضرورية، وhealthcheck.
- GitHub Actions workflow لفحوص الصياغة والاختبارات وBandit وpip-audit وDocker Compose config وبناء صورة API.
- Dependabot لمراجعة تحديثات Python وGitHub Actions وصورة Docker دورياً.
- `.dockerignore` لمنع إرسال ملفات البيئة والاختبارات والوثائق وقواعد البيانات إلى سياق بناء API دون حاجة.
- تحديث نسخة PWA cache إلى `mishkat-shell-v2` لإبطال ملفات الواجهة القديمة.
- تحديث README وChangelog ومذكرة التسليم والبرومبت الهندسي للمرحلة التالية.

## ما تم فحصه فعلياً في بيئة الإنشاء

- `python -m compileall -q backend`: نجح.
- `node --check frontend/assets/app.js`: نجح.
- `python -m pytest -q`: نجحت 21 اختباراً آلياً.
- تحليل `docker-compose.yml` و`.github/workflows/ci.yml` كـ YAML: نجح.
- اختبارات TestClient لمسارات API غير المعتمدة على قاعدة بيانات حقيقية: نجحت.
- اختبارات mock لمسارات NEXORA تثبت أن هوية المستخدم المصادق، وليست `owner_id` من العميل، تستخدم في الاستعلامات.
- اختبار أن سحب الموافقة يمنع تحديث أهداف التعلم.
- اختبار مسار تصدير بيانات المتعلم وسجل الموافقة مع mock database.
- إعدادات الإنتاج ترفض development auth والقيم التجريبية المعروفة.
- فشل اختبار التصفح المرئي بمتصفح Playwright لأن بيئة المتصفح أعادت `ERR_BLOCKED_BY_ADMINISTRATOR` عند فتح localhost؛ لذلك لم أسجل نتيجة اختبار بصري ناجح.

## ما لم يتم اختباره أو لم يكتمل

- Docker executable غير متاح في بيئة الإنشاء؛ لم تُشغّل الحاويات أو صورة Docker فعلياً.
- لا يوجد PostgreSQL/PostGIS فعلي متاح هنا؛ لم تُختبر SQL migrations أو سياسات RLS على قاعدة حقيقية.
- migration NEXORA الجديدة لم تُطبق على أحجام بيانات قائمة؛ نفّذ `scripts/migrate-nexora-windows.ps1` عند وجود قاعدة NEXORA قديمة.
- لم يتم تنفيذ اختبارات A/B فعلية لعزل مالكين داخل قواعد البيانات الخمس.
- لم يتم اختبار NASA POWER على شبكة خارجية فعلية أو إثبات حفظ سجلات في PostgreSQL حقيقي.
- موصلات WHO/FAO/WRI/Ember/UNESCO/CAPMAS ما زالت في سجل المصادر أو تحتاج تطويراً وربطاً.
- لا يوجد مزود LLM متصل، ولا تدريب أو تقييم لنماذج قطاعية.
- لا يوجد تدفق هوية إنتاجي مكتمل في الواجهة، ولا staging/production deployment، ولا اختبار اختراق خارجي.
- GitHub Actions workflow أُنشئ وتحقق من صياغته محلياً، لكنه لم يُشغّل على GitHub؛ لم تنفذ فحوص Bandit وpip-audit في هذه البيئة.
- NEXORA pilot يعتمد تأكيد البالغ ذاتياً، وليس تحققاً من الهوية أو العمر. لا تستخدمه للقاصرين.
- لا يوجد بعد حذف شامل لبيانات المتعلم؛ التصدير متاح، أما الحذف والاحتفاظ فيحتاجان سياسة تنفيذية وقانونية موثقة.
- لا يوجد تطبيق Android/iOS أصلي أو مزود إشعارات أو مساعد AI.

## قيود الإصدار

- الحزمة ليست Production Release ولا شهادة امتثال.
- لا تدعي دقة 100% أو خلوها من الأخطاء.
- لا يوجد تشخيص طبي أو أوامر تحكم للمياه/الطاقة أو توصيات مبيدات.
- لا توجد بيانات قطاعية محلية تشغيلية حقيقية مرفقة بالحزمة. موصل NASA مكتوب، لكنه غير مثبت الاتصال والتخزين في هذه البيئة.

## الخطوات التالية بالترتيب

1. تشغيل Docker Compose محلياً والتحقق من جاهزية قواعد البيانات الخمس.
2. تشغيل migration NEXORA على أي قاعدة قديمة، دون حذف volumes.
3. تنفيذ اختبارات RLS وA/B لكل جدول ومسار على PostgreSQL فعلي.
4. إكمال هوية الإنتاج والجلسات وعضويات المؤسسات والصلاحيات قبل النشر العام.
5. تنفيذ browser E2E على بيئة محلية لدى المطور وعلى GitHub CI، وفحص RTL وإمكانية الوصول.
6. إكمال موصل واحد مرخص ومثبت لكل مجال ثم تطوير MVP تشغيلي حقيقي لكل قطاع.
7. لا تفعّل AI الطبي أو التشغيلي قبل شراكات البيانات والموافقات والتحقق المستقل.
