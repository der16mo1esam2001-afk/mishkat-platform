## 3. جرد المكونات والفجوات المكتشفة مقارنة بالماستر برومبت

1. **قواعد البيانات الخمس:**
   - مخططات SQL وسياسات RLS الخمس موجودة ومطبقة بعناية (`02-schema.sql` في كل قطاع).
   - لا يوجد قاعدة مشتركة تخلط البيانات الحساسة.
   - غياب Docker يمنع تشغيل خوادم PostgreSQL الخمسة في الخلفية محلياً. الحل الهندسي: بناء واختبار محاكاة عزل دقيقة (In-Memory/Mock & SQL Grammar AST Tests) تؤكد صحة المعاملات، وسياسات RLS، والفصل التام بين المالكين.

2. **موصلات البيانات (Data Connectors):**
   - موصل NASA POWER كان مدمجاً مباشرة داخل `backend/app/main.py` بدلاً من هيكل موصلات مجرد وموحد.
   - باقي المصادر (WHO, AQUASTAT, WRI, FAOSTAT, Ember, UNESCO) مسجلة فقط في الكتالوج (`catalog.py`) كبيانات وصفية دون محولات برمجية موحدة تتبع إطار الحوكمة (Provenance, License, Schema validation).

3. **المسارات القطاعية الكاملة (Vertical Slices):**
   - قطاع NEXORA يحتوي على مسار عمل أولي لملف التعلم والأهداف والمسارات والتصدير وسحب الموافقة. ينقصه دورة التقييم والاحتفاظ المعرفي وتتبع المصادر ومسار الحذف.
   - القطاعات الأربعة الأخرى (VITALIS, AQUANEX, AGRONEX, ENERGIS) ليس لها مسارات CRUD كاملة في الـ API بعد، وتقتصر على `activity` و`snapshot`.

4. **بوابة الذكاء الاصطناعي (AI Gateway) والمساعد:**
   - مسار `/api/v1/ai/status` يعيد `not_configured` بصورة صريحة وآمنة.
   - لا توجد طبقة تجريد لخوادم النماذج (Model Providers)، ولا حماية من حقن التوجيهات (Prompt Injection Defense)، ولا تتبع للاقتباسات، ولا وكيل منخفض المخاطر لـ NEXORA.

5. **الهوية والصلاحيات (RBAC & OIDC Adapter):**
   - المصادقة الحالية تدعم `development` token ثابت، أو Supabase JWKS عبر الإنترنت عند تكوينه.
   - يلزم وجود محول OIDC مرن وقابل للاختبار محلياً بمفاتيح RSA/EC مصطنعة للاختبارات السلبية واختبارات الصلاحيات (RBAC: Admin, Operator, Auditor, Learner).

6. **الواجهة وتجربة المستخدم (Frontend):**
   - الواجهة تدعم PWA بهوية بصرية مميزة، ولكن تفاعلات القطاعات الأخرى (غير NEXORA) كانت للعرض فقط. يلزم تمكين واجهات التفاعل الكاملة مع كل مسار عمل قطاعي.
