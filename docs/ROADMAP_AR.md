# خارطة طريق مِشكاة — الإصدار 0.2.0 وما بعده

## الوضع الحالي — 0.2.0 (Engineering Pilot)
- خمس قواعد بيانات PostgreSQL منفصلة ومخططات قطاعية أولية.
- API FastAPI مع مصادقة تطوير محلية ومسار JWKS غير مكتمل الإعداد الإنتاجي.
- بوابات حماية على إعدادات الإنتاج وSecurity Headers وAPI no-store.
- سجل نشاط الاستيراد والنماذج لكل نطاق.
- موصل NASA POWER أولي إلى AGRONEX وENERGIS.
- وظائف NEXORA أولية: ملف متعلم للبالغين، موافقة بإصدار، أهداف، ومسارات؛ مع سجل موافقات غير قابل للتعديل من دور التطبيق وسحب للموافقة.
- PWA shell لا يخزن API أو السجلات الحساسة.
- اختبارات آلية أولية؛ لم يتم اختبار Docker/PostgreSQL الفعلي أو RLS داخل حاويات في بيئة البناء.

## المرحلة 1 — تثبيت الأساس (Release Hardening)
- مراجعة migrations على PostgreSQL/PostGIS فعليين.
- اختبار RLS A/B في قواعد البيانات الخمس.
- هوية إنتاجية OIDC/Supabase Auth مع MFA عند الحاجة وتدفق جلسات آمن.
- عزل المؤسسات والعضويات عند تصميم multi-tenant مع اختبار شامل.
- CI/CD، فحص dependencies/SBOM/secrets/container، واختبارات تكامل وE2E.
- إدارة الأسرار، CSP/HSTS، مراقبة، نسخ احتياطية واختبار استعادة.
- ترحيل NEXORA learner-consents إلى قواعد NEXORA القائمة.

## المرحلة 2 — سجل بيانات ومصادر موثوقة
- إطار موحد للموصلات مع adapters منفصلة.
- سجل provenance وlicense/version/source metadata.
- موصل موثوق لكل قطاع بعد التحقق من API schema والترخيص.
- ingestion jobs، retry/idempotency، مراقبة freshness، وdead-letter.
- اختبارات جودة بيانات ووحدات وتواريخ وجغرافيا.

## المرحلة 3 — MVP قطاعي قابل للاستخدام
- VITALIS: إدارة ملفات مستعارة ومواعيد/زيارات وموافقات ومتابعة غير تشخيصية، بالتعاون مع جهة صحية.
- AQUANEX: سجل أصول وشبكات وعينات وقراءات فعلية من مرفق شريك.
- AGRONEX: مزرعة/قطعة/دورة محصول واحدة، وطقس/تربة/ري/حصاد حقيقي.
- ENERGIS: منشأة واحدة وعدادات فعلية وتحليل استهلاك تاريخي.
- NEXORA: مسار تعلم واحد مكتمل بالمحتوى المرخص والتقييم والاحتفاظ.

## المرحلة 4 — الذكاء الاصطناعي المتخصص
- AI Gateway بمفاتيح خادمية واتفاقيات معالجة.
- RAG مع مصادر مرخصة واستشهادات قابلة للتحقق.
- Model registry وmodel cards واختبارات ومراقبة drift.
- إطلاق نماذج وصفية/تنبؤية منخفضة المخاطر أولاً بعد وجود بيانات كافية.
- إبقاء التشخيص الطبي والتحكم في البنية التحتية مؤجلين حتى الاعتماد المستقل.

## المرحلة 5 — التجربة المؤسسية والتشغيل
- حسابات المؤسسات والفرق والصلاحيات.
- SSO، audit exports، retention/deletion/data subject requests.
- تقارير أثر تقارن baseline بنتائج التجربة.
- Monitoring/alerting/SLOs، backup/restore، incident response، rollback.

## المرحلة 6 — التوسع العالمي
- لغات إضافية ومناطق زمنية ووحدات محلية.
- تجربة الهاتف الأصلية فقط بعد تثبيت عقود API واحتياجات الأجهزة/الإشعارات/العمل دون اتصال.
- مراجعة قانونية لكل دولة ومجال.
- شراكات بحثية وميدانية واعتمادات مرتبطة بنطاق المنتج الفعلي.
- التوسع متعدد المناطق وإقامة البيانات حسب القوانين والعقود.

## قاعدة الانتقال بين المراحل
لا ينتقل المشروع إلى المرحلة التالية بسبب مرور الوقت أو اكتمال التصميم؛ ينتقل فقط عند اجتياز معايير القبول والاختبارات الموثقة لكل مرحلة.
