# دليل تنفيذ مِشكاة باستخدام Antigravity

## قبل البدء

1. فك ضغط `MISHKAT-Platform-v0.2.0.zip` في مجلد عمل واضح، مثل `D:\Projects\mishkat-platform`.
2. افتح Google Antigravity على Windows.
3. اختر **Open Folder** ثم اختر مجلد `mishkat-platform` نفسه، وليس مجلد `docs` أو ملف ZIP.
4. افتح الملفات التالية داخل مساحة العمل:
   - `AGENTS.md`
   - `README_AR.md`
   - `docs/BUILD_STATUS_AR.md`
   - `docs/ROADMAP_AR.md`
   - `docs/MASTER_PROMPT_NEXT_PHASE_AR.md`

## المرحلة الأولى — مراجعة المستودع والخطة

اطلب من الوكيل:

> اقرأ AGENTS.md وREADME_AR.md وdocs/BUILD_STATUS_AR.md وdocs/ROADMAP_AR.md وdocs/MASTER_PROMPT_NEXT_PHASE_AR.md. افحص المستودع الحالي كما هو. لا تعدل الملفات ولا تنفذ migrations ولا تتصل بخدمات إنتاج. أخرج خريطة المجلدات، وتدفق البيانات، والاعتماديات، والقيود الفعلية، وخطة تنفيذ Milestone A فقط مع الملفات التي ستتغير واختبارات القبول والمخاطر.

راجع الخطة قبل السماح بالتنفيذ.

## المرحلة الثانية — التنفيذ المقيد

بعد مراجعة الخطة، اطلب:

> نفّذ Milestone A فقط من docs/MASTER_PROMPT_NEXT_PHASE_AR.md. أنشئ branch أو checkpoint. نفّذ التغييرات الضرورية بأصغر diff ممكن. لا تنتقل تلقائياً إلى Milestone B. بعد التنفيذ شغّل الاختبارات المتاحة، وسجل الأوامر ونتائجها الفعلية، وحدّث docs/BUILD_STATUS_AR.md. لا تدّعِ أن PostgreSQL أو RLS أو المتصفح أو النشر تم اختباره إن لم تنفذ ذلك فعلياً.

كرر النمط نفسه لكل Milestone لاحق؛ مرحلة واحدة في كل مرة.

## المرحلة الثالثة — الاختبار المرئي

بعد تشغيل التطبيق محلياً، اطلب من Antigravity استخدام browser workflow المتاح في إصدارك:

> افتح التطبيق المحلي، اختبر التنقل بين النظرة العامة والقطاعات الخمسة، واختبر أحجام 390px و768px و1440px، واجهة RTL، النماذج، الحالات الفارغة، رسائل الخطأ، وعمليات التحميل. راقب Console والأخطاء وطلبات الشبكة الفاشلة. احفظ Screenshots فعلية مع تاريخ وبيئة الاختبار. لا تستخدم بيانات حقيقية أو أسراراً.

إذا لم تتوفر ميزة Browser Agent في الإصدار/الحساب، استخدم Chrome DevTools أو Playwright محلياً وسجّل القيد.

## المرحلة الرابعة — مراجعة مستقلة باستخدام Codex

بعد كل Milestone، افتح نفس repository في Codex واطلب منه تنفيذ مراجعة مستقلة باستخدام `docs/CODEX_REVIEW_PROMPT_AR.md`. لا تجعل Antigravity وCodex يعدّلان الملف نفسه في الوقت نفسه.

## ما لا تمنحه للوكيل تلقائياً

لا توافق دون مراجعة بشرية صريحة على:
- `docker compose down -v` أو حذف قواعد البيانات/volumes.
- تطبيق migration على قاعدة إنتاج.
- تحميل بيانات مرضى أو طلاب أو منشآت حساسة إلى خدمة خارجية.
- إضافة مفاتيح حقيقية أو أسرار في ملفات الكود.
- تغيير DNS أو النطاق أو إعدادات الاستضافة.
- نشر production أو إرسال رسائل فعلية أو تشغيل أجهزة ومعدات.

## بوابة نهاية كل مرحلة

لا تقبل عبارة "done" وحدها. اطلب: ملفات تغيرت، diff، أوامر اختبار شُغلت، عدد نجاح/فشل، سجلات أو Screenshots، نتائج مراجعة أمنية، ما لم يُختبر، والمخاطر المفتوحة. لا تسمح بالانتقال إلى المرحلة التالية قبل قبول المخرجات.
