# نظام التصميم — مِشكاة | MISHKAT

## 1. الفكرة البصرية

**Calm Authority — أصالة هادئة مع ذكاء معاصر.** يجب أن يظهر المنتج كمنظومة علمية ومؤسسية موثوقة، لا كتطبيق ترفيهي أو لوحة ألوان صاخبة. الهوية تجمع الخط العربي الأصيل مع وضوح أدوات البيانات الحديثة.

## 2. لوحة الألوان الحالية

| Token | Hex | الاستخدام |
|---|---|---|
| Ink / النص الرئيسي | `#17343A` | النصوص والعناوين الداكنة |
| Deep / الخلفية العميقة | `#102C32` | الشريط الجانبي والعناصر الأساسية |
| Deep 2 | `#193B41` | المستويات الثانوية في الواجهة الداكنة |
| Gold | `#D9BD83` | إبرازات الهوية والعناصر المهمة، لا نصوص صغيرة على خلفيات فاتحة |
| Canvas | `#F4F4EF` | خلفية التطبيق |
| Paper | `#FFFEFA` | البطاقات ومساحات المحتوى |
| Line | `#E5E8E1` | الحدود والفواصل |
| Muted | `#7A8C8C` | النصوص الثانوية |

### ألوان النطاقات

- VITALIS: أخضر طبي هادئ `#69AD99`.
- AQUANEX: أزرق مائي `#64A8CD`.
- AGRONEX: أخضر نباتي `#8AAB68`.
- ENERGIS: كهرماني شمسي `#C79B4A`.
- NEXORA: بنفسجي معرفي `#9581C3`.

هذه ألوان هوية واجهة مقترحة وليست ترميزاً طبياً أو تشغيلياً للخطورة. حالات النجاح والتحذير والخطر تحتاج tokens مستقلة ومعايير contrast واضحة.

## 3. الخطوط واللغة

- العربية: Noto Sans Arabic أو IBM Plex Sans Arabic للواجهات والنصوص الطويلة، ويمكن استخدام Noto Naskh Arabic للعناوين التحريرية عند توافره محلياً.
- الإنجليزية والأرقام: Inter أو system sans-serif.
- يجب ألا يعتمد تحميل الخط على CDN خارجي في الإنتاج ما لم يوجد سبب واعتماد أداء وخصوصية واضح.
- الواجهة الأساسية RTL، مع دعم LTR حقيقي للإنجليزية عبر CSS logical properties، وليس قلباً سطحياً للمحاذاة.

## 4. المكونات

- Sidebar داكن قابل للطي على الهاتف.
- Topbar يوضح الموقع الحالي والبحث والحساب وحالة البيئة.
- Portfolio status strip لا يعرض إلا الحالات الفعلية التي عادت من API.
- Domain cards بخمسة ألوان ثابتة.
- Panels بسطوح فاتحة وحدود رقيقة ومساحات تنفس.
- Data provenance badges تشرح measured / aggregate / remote-sensed / estimated / forecast / synthetic-fixture.
- Forms ذات labels دائمة ورسائل خطأ عربية واضحة.
- Tables قابلة للتمرير مع ترويسات ثابتة عند الحاجة.
- Charts تعرض الوحدة والفترة والمصدر ونوع السلسلة وعدم اليقين.

## 5. قواعد إمكانية الوصول

- استهداف WCAG 2.2 AA كهدف هندسي، ثم اختبار يدوي وأدوات؛ لا تدّعِ المطابقة قبل التدقيق.
- جميع الوظائف قابلة للاستخدام بلوحة المفاتيح، مع focus واضح لا يُحجب.
- لا تستخدم اللون وحده لتوصيل الحالة.
- احترام `prefers-reduced-motion`.
- دعم تكبير النص والواجهات، captions/transcripts للمحتوى الصوتي والمرئي، وبدائل نصية للرسوم والخرائط.
- حجم هدف اللمس مناسب للهاتف، ورسائل الخطأ مرتبطة بالحقول.

## 6. الحركة والرسوم

- انتقالات قصيرة وهادئة؛ لا حركات متكررة أو أضواء نابضة على لوحات حساسة.
- لا تستخدم مؤشرات تحميل مزيفة أو رسوم بيانية تجميلية.
- لا تعرض أرقام KPI ثابتة على أنها حقيقية. عند غياب البيانات، اشرح سبب غيابها.

## 7. متطلبات الشاشة

- Desktop: عرض محتوى مريح، قائمة جانبية، جداول متعددة الأعمدة.
- Tablet: تخفيض الأعمدة إلى بطاقات أو صفوف مكدسة.
- Mobile: واجهة عمودية، أزرار لمس، نماذج قصيرة، وجداول قابلة للتمرير دون قص المعلومات.
- اختبار العرض على 360px و390px و768px و1024px و1440px على الأقل.

## 8. معيار قبول بصري

- لا يوجد overflow أفقي غير مقصود.
- لا يوجد نص عربي مكسور/معكوس أو تداخل بين RTL وLTR.
- كل عنصر تفاعلي له حالة hover/focus/disabled/loading/error.
- جميع الصور لها alt أو `alt=""` إذا كانت زخرفية فقط.
- Contrast مقاس آلياً ومراجع يدوياً.
- Screenshots موثقة لكل صفحة رئيسية وعلى 3 أحجام شاشة على الأقل، بعد تشغيل التطبيق فعلياً.
