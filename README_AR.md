# مِشكاة | MISHKAT — منصة الذكاء التطبيقي متعددة القطاعات

**الإصدار:** 0.2.0  
**الوصف:** منصة موحدة بتجربة واحدة وخمسة نطاقات بيانات وخدمات قطاعية مستقلة.

> هذه حزمة هندسية محلية/تجريبية وليست إصدار إنتاج أو شهادة امتثال أو منتجاً طبياً معتمداً. لا يوجد ضمان انعدام الأخطاء أو دقة 100%. لا تستخدم بيانات أشخاص أو منشآت حقيقية قبل إكمال إعداد الهوية، والخصوصية، والتراخيص، والاختبارات، والموافقات اللازمة.

## 1. مكوّنات المنصة

- **VITALIS AI:** بنية تأسيسية لدعم تنظيم المعلومات الصحية ومتابعة الرعاية. لا تقدم تشخيصاً أو وصف علاج.
- **AQUANEX:** بنية بيانات مكانية ومؤشرات مياه وقراءات حساسات. لا تتحكم بالمضخات أو الصمامات.
- **AGRONEX:** بيانات المزارع والمحاصيل والطقس والري والحصاد. لا تقدم أوامر مبيدات.
- **ENERGIS:** بيانات المنشآت والعدادات والموارد الشمسية والطاقة. لا تتحكم بالشبكة أو المعدات.
- **NEXORA:** مساحة أولية للبالغين تشمل ملف تعلم وموافقة وأهداف ومسارات وتصدير بيانات الحساب.
- **MISHKAT Core:** بوابة موحدة للتنقل ومصادر البيانات وحالة الخدمات وسجل النشاط.

## 2. ما أضيف في 0.2.0

- خمس قواعد PostgreSQL مستقلة، وخمس قواعد صلاحيات/RLS لكل قطاع.
- مفاتيح أجنبية مركبة تربط السجلات التابعة بمالكها لتقليل مخاطر الربط عبر المالكين.
- Backend بـ FastAPI مع تهيئة مستقلة لمجمعات اتصالات قواعد البيانات الخمس.
- معرّف طلب `X-Request-ID` وترويسات أمنية ومنع التخزين المؤقت لاستجابات API.
- حماية إعدادات الإنتاج من تفعيل مصادقة التطوير أو استخدام CORS عام أو قيم اتصال تجريبية.
- موصل NASA POWER يومي: مجتمع `AG` لبيانات المناخ الزراعي في AGRONEX، ومجتمع `RE` للإشعاع الشمسي في ENERGIS.
- سجل عمليات الاستيراد والنماذج وأحداث التدقيق لكل نطاق.
- NEXORA pilot: ملف تعلم للبالغين فقط، سجل موافقات غير قابل للتعديل من دور التطبيق، أهداف ومسارات، وسحب الموافقة.
- تصدير بيانات NEXORA بصيغة JSON للحساب المصادق عليه.
- سحب الموافقة يمنع عمليات إنشاء/تعديل أهداف التعلم؛ السجلات السابقة لا تحذف تلقائياً.
- Docker API يعمل بمستخدم غير root، وملفات نظام للقراءة فقط، و`no-new-privileges`.
- PWA shell لا يخزن استجابات API أو بيانات المستخدم الحساسة.
- GitHub Actions CI لفحوص الصياغة والاختبارات وفحص Bandit وتدقيق التبعيات وبناء صورة API.
- Dependabot لتحديث التبعيات والأدوات، وملفات `.dockerignore` و`.editorconfig`، ونظام تصميم وسجل خصائص مرتب حسب الأولوية.

## 3. حدود النسخة

- لا يوجد مزود LLM متصل، ولا مساعد AI فعّال، ولا نماذج قطاعية مدربة أو مقيمة.
- موصل NASA POWER مكتوب برمجياً؛ لم يثبت بعد في بيئة الإنشاء استدعاء حي وحفظ ناجح في PostgreSQL حقيقي.
- بقية مصادر WHO وFAO وWRI وEmber وUNESCO وCAPMAS وNREA موثقة في سجل المصادر؛ لا يعني ذلك أن كل موصلاتها قد نُفذت أو اتصلت.
- NEXORA حالياً pilot بالغين بتأكيد عمر ذاتي فقط، وليس تحقق هوية أو عمر. لا تسجل القاصرين.
- تم تنفيذ ملف المتعلم والأهداف والمسارات والتصدير، وليس نظام تعلم تكيفي كاملاً أو محتوى مرخصاً أو قياس إتقان.
- واجهة الهاتف هي PWA قابلة للتثبيت، وليست تطبيقاً أصلياً منشوراً في المتاجر.
- واجهة تسجيل الدخول الإنتاجي وربط Supabase/OIDC ما زالت تتطلب الإعداد؛ رمز التطوير محلي فقط.

## 4. تشغيل Windows 11 محلياً

المتطلبات: Docker Desktop حديث مع Docker Compose v2، وPowerShell، وPython 3.12 للاختبارات المحلية، وNode.js 22 لفحص JavaScript.

1. فك ضغط مجلد المشروع وافتح PowerShell من جذر `mishkat-platform`.
2. شغّل:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. استبدل كلمات المرور والأسرار التجريبية بقيم عشوائية قوية قبل التشغيل. لا تستخدم القيم التي تبدأ بـ `replace-with` أو `local-please-change`.
4. شغّل:

   ```powershell
   .\scripts\start-windows.ps1
   ```

   أو:

   ```powershell
   docker compose up --build -d
   ```

5. افتح `http://localhost:8000` واضغط **بدء جلسة تطوير محلية** ثم **فحص الاتصالات**.

لا تعرض المنفذ على الإنترنت. رمز التطوير لهوية ثابتة محلية وينتهي خلال ساعتين، ولا يصلح للمستخدمين الحقيقيين.

### ترحيل NEXORA عند وجود قاعدة قديمة

ملف `database/nexora/03-learner-consents.sql` يعمل تلقائياً عند إنشاء حجم قاعدة NEXORA لأول مرة. إذا كان لديك حجم بيانات سابق، لا تحذفه. بعد تشغيل قاعدة البيانات نفّذ:

```powershell
.\scripts\migrate-nexora-windows.ps1
```

لا تستخدم `docker compose down -v` إلا إذا كنت تقصد حذف بيانات قواعد البيانات الخمس محلياً. هذا الأمر مدمر للبيانات.

## 5. نقاط API الرئيسية

كل المسارات التالية تحت `/api/v1` وتتطلب Bearer token باستثناء liveness وصفحات الواجهة:

| المسار | الاستخدام |
|---|---|
| `/health/live` | فحص أن عملية API تعمل |
| `/health/ready` | حالة اتصالات قواعد البيانات الخمس |
| `/system/overview` | نظرة حالة المنصة للمستخدم المصادق |
| `/workspaces` | قائمة القطاعات |
| `/evidence/sources` | سجل مصادر البيانات |
| `/ai/status` | يوضح أن محرك AI غير موصل |
| `/connectors/nasa-power/fetch` | جلب وحفظ بيانات NASA POWER ضمن القاعدة المالكة |
| `/modules/{domain}/snapshot` | ملخص أعداد سجلات القطاع |
| `/modules/{domain}/activity` | استيرادات البيانات وسجل النماذج والتدقيق |
| `/nexora/profile` | ملف المتعلم وموافقة التخزين |
| `/nexora/goals` | أهداف التعلم |
| `/nexora/paths` | مسارات التعلم |
| `/nexora/export` | تصدير ملف المتعلم وأهدافه ومساراته وسجل موافقته |
| `/nexora/profile/revoke-consent` | سحب موافقة التخزين وإيقاف كتابات التعلم |

## 6. مصادر البيانات

راجع `docs/SOURCES_AR.md`. سجل المصدر يميز بين API منفذ، ومصدر موثق فقط، ومصدر يحتاج اعتماداً/ترخيصاً، ومصدر يتطلب سجلات جهة تشغيلية.

**NASA POWER:** يوفر بيانات شبكة جغرافية وطقس/موارد شمسية؛ لا يحل محل حساس مزرعة أو عداد كهرباء.

**البيانات الصحية والمائية والطاقة:** بيانات WHO أو WRI الإحصائية ليست سجلات مرضى أو قياسات عدادات حية. نحتاج وصولاً قانونياً وميدانياً لهذه البيانات.

## 7. الاختبارات المحلية

من جذر المشروع:

```powershell
python -m pip install -r backend/requirements.txt pytest pyyaml
python -m compileall -q backend
node --check frontend/assets/app.js
python -m pytest -q
```

CI على GitHub يشغّل أيضاً Bandit وpip-audit وDocker build. نتائج CI الفعلية تظهر بعد رفع المشروع إلى مستودع GitHub وتفعيل Actions؛ وجود ملف workflow لا يعني أنه نُفذ.

## 8. متطلبات ما قبل الإنتاج

1. ربط هوية إنتاجية حقيقية، وتدفق تسجيل دخول/خروج وتجديد الجلسة في الواجهة، وMFA/SSO حسب الحاجة.
2. إجراء اختبارات PostgreSQL/PostGIS فعلية واختبارات RLS بين مستخدمين A/B على كل جدول ومسار.
3. إكمال موصلات البيانات حسب الترخيص والمخططات والتحقق من القيم والوحدات وتواريخ التحديث.
4. إكمال workflows التشغيلية الخمسة، وليس فقط المخططات وقوائم المؤشرات.
5. بناء AI gateway في الخادم فقط، بمزود موثق ومفاتيح في مدير أسرار وتقييمات مستقلة وحدود استخدام.
6. إعداد تصدير/حذف بيانات شامل وسياسات احتفاظ وموافقات قابلة للمراجعة لكل مجال.
7. اختبار واجهة حقيقي على Chromium وFirefox/WebKit، مع فحص إمكانية الوصول WCAG 2.2 AA.
8. مراجعة قانونية وأخلاقية متخصصة للصحة والقاصرين والبنية التحتية والخصوصية في كل دولة مستهدفة.
9. staging منفصلة، مراقبة، سجلات منقحة، نسخ احتياطية، اختبار استعادة، مسح أسرار وتبعيات، وفحص اختراق خارجي.
10. تحديد SLO وقياس تكاليف التشغيل والخدمات الخارجية وخطة rollback قبل النشر.
